# @jpmergulhao/pixelflow-types

As a tool designed with a **TypeScript-first** approach, the Types package is the core contract of the PixelFlow ecosystem. It ensures that the data fired by the browser (Client-Side) shares the exact same format as the data expected by your backend (Server-Side). This **Isomorphism** prevents contract errors that would otherwise cause conversion tracking loss.

As a developer consuming this library, **you will rarely need to interact with or import this package directly**. All typing intelligence and autocomplete features (IntelliSense) are automatically inferred by your IDE (like VS Code) when you use the functions from the `Client`, `React`, or `Server` packages.

---

## Base Event Configuration (`BaseEvent`)

To guarantee standardization and the proper handling of sensitive data, all PixelFlow event methods require a base configuration. The payloads for all events, whether client or server-side, are extensions of this `BaseEvent` interface. 

It contains the following fundamental arguments:

*   **`eventId`** (`string`): Unique identifier for the event (e.g., an order ID or a session hash). It is **strictly required** for advertising platforms to perform automatic deduplication when the event is fired simultaneously by the Client-Side and Server-Side (CAPI).
*   **`hasConsented`** (`boolean`): Mandatory flag to authorize the event firing. It ensures your application remains compliant with privacy laws (GDPR/LGPD/CCPA). If passed as `false`, PixelFlow will silently abort the data transmission.
*   **`platforms`** (`array`): A declarative list containing the specific platforms that should receive the event. Accepted values: `["meta", "google", "pinterest", "tiktok"]`.
*   **`currency`** (`string`): The commercial transaction currency (e.g., `"USD"`, `"BRL"`). Used primarily in events involving financial value, such as `trackAddToCart` and `trackPurchase`.
*   **`value`** (`number` - Float/Decimal): The total purchase or product value on your site. Although this field is optional in some events, sending the item's value helps AI algorithms (especially Meta and TikTok) understand the purchasing power and average ticket of that specific user.

## Specific Event Configurations

Depending on the tracking event you invoke, the payload may accept or require additional specific properties. 

### Commerce & Sales
*   **`orderId`** (`string`): The unique order identifier generated by your backend or partner platforms (like Shopify or Stripe). GA4 and Pinterest actively use this to prevent double-counting the same sale.
*   **`paymentType`** (`string`): The payment method used by your customer (e.g., `credit_card`, `paypal`, `pix`). Highly useful for Google Analytics 4 (GA4) to understand which payment method converts best.
*   **`contentType`** (`'product' | 'product_group'`): If the identifier passed in `contentIds` or `contents` is for a single product, use `'product'`. If it identifies a group of products, use `'product_group'`.
*   **`subscriptionTier`** (`string`): The level or plan of a subscription (e.g., `'Premium'`, `'Basic'`, `'Newsletter'`).
*   **`predictedLtv`** (`number` - Float): *(Meta Exclusive)* The predicted lifetime value of a subscriber, as defined by the advertiser, if they convert to a paid plan.
*   **`trialTier`** (`string`): The name or level of the plan the user started a free trial for.
*   **`donationCampaign`** (`string`): The name of the campaign or cause.

### Lead & User Lifecycle
*   **`registrationMethod`** (`string`): The method used to sign up (e.g., `'email'`, `'google'`, `'facebook'`). Excellent for GA4 to track where users originate from.
*   **`loginMethod`** (`string`): The method by which the user logged in.
*   **`status`** (`boolean`): The status of the registration or application.
*   **`leadType`** (`string`): Classification or origin of the captured lead (e.g., `'Ebook'`, `'Consultation'`).
*   **`contactMethod`** (`string`): The channel through which the user contacted you (e.g., `'whatsapp'`, `'email'`, `'phone'`).
*   **`applicationId`** (`string`): Unique identifier for a submitted/approved application or proposal.
*   **`applicationType`** (`string`): The type of the application or proposal.

### Engagement & Discovery
*   **`searchString`** (`string`): The search query entered in your site's search field.
*   **`fileName`** (`string`): The name of the downloaded file.
*   **`fileType`** (`string`): The extension/type of the file (e.g., `'pdf'`, `'mp4'`).
*   **`customizationDetail`** (`string`): Details or options the user selected during product customization.
*   **`locationName`** (`string`): The searched term to find a physical store/location.
*   **`scheduleType`** (`string`): The type or name of the scheduled appointment.
*   **`scheduleDate`** (`string`): The date or time for which the appointment was scheduled.
*   **`shareMethod`** (`string`): The channel through which the user shared the content/product (e.g., `'whatsapp'`, `'twitter'`, `'copy_link'`).

## Catalog & Product Arrays

For events involving products (like Add to Cart, Checkout, and Purchase), PixelFlow uses declarative arrays. **You only need to pass the product list once in this clean format, and PixelFlow automatically handles formatting it to each platform's specific, complex standard.**

*   **`contentIds`** (`string[]`): A simple declarative list containing the IDs of the products that triggered the event.
*   **`contents`** (`ProductItem[]`): A declarative list containing the event items in detail. Used for dynamic Catalog and Dynamic Product Ads (DPA) remarketing campaigns.
    *   **`id`** (`string`): Item identifier.
    *   **`name`** (`string`): Item name.
    *   **`price`** (`number` - Float/Decimal): Price of the item.
    *   **`quantity`** (`number` - Integer): Number of units for the item.
    *   **`category`** (`string` - Optional): Item category.

> **Note:** The exact required data contract (mandatory vs. optional properties) will be clearly detailed on the specific documentation page for each individual event.
